# HBM Architecture Explorer

AI 워크로드에서 발생하는 연산과 데이터 이동을 추정하고, 가상 하드웨어 자원과 사양 변경의 영향을 탐색하는 로컬 웹 앱입니다.

> **구현 상태:** P0 구현 진행 중. 네 Operator의 계산 엔진, 고정 하드웨어 도식, 입력·근거 탐색, 민감도와 기준안 비교가 연결되어 있습니다. 자동 테스트·타입 검사·프로덕션 빌드는 코드 수준 확인이며, 브라우저 반응형·키보드·사용자 판단 인수는 별도 확인이 필요합니다. 기본값은 가상 제안값이며 실제 장치 사양이나 성능 예측을 뜻하지 않습니다.

## 목표

하드웨어 구조 위에서 데이터가 어디에 저장되고, 어떻게 이동·재사용되며, 어디에서 계산되는지 이해합니다. 그 이해를 토대로 제한 자원을 찾고 시스템 사양을 바꿔 기준안과 비교한 뒤 선택 근거를 확인합니다. P0의 대상은 선택한 워크로드를 실행하는 가상 시스템입니다.

기본 입력의 결과 요약을 먼저 보여주고 선택 결과의 ‘자세히 보기’, 자원별 사양 설정, 오류의 ‘입력 수정’으로 다음 행동을 안내합니다. 데이터의 논리 크기와 반복을 포함한 이동량은 구분해 표시합니다.

중앙의 하드웨어 도식은 단계와 사양을 바꿔도 위치를 유지합니다. 데이터 경로와 재사용을 그 위에 표시하고, 선택한 자원의 사양을 바로 수정할 수 있게 합니다. 긴 산식과 상세 표는 필요한 때 펼칩니다. 기본 조작은 단계 선택과 자원 사양 수정이며, 별도 선택안 저장·전체 입력 역탐색·시간축 타임라인·그래프 자유 편집은 후속 범위입니다.

## P0 범위

- **워크로드:** GEMM/GEMV, Dense Attention prefill, 균등 라우팅 MoE, 논리적 Rank 기반 Collective
- **하드웨어:** 사용자가 편집할 수 있는 가상 Accelerator 1개와 논리적 Rank 연결
- **분석:** FLOPs, 데이터 이동량, 추정 단계 시간, 병목 설명, Compute·SRAM BW·HBM BW·Link BW 각각 2배 민감도
- **인터페이스:** React + TypeScript, 고정 배치의 단순 SVG 하드웨어 도식, 브라우저 내 TypeScript 계산 엔진
- **추적:** 수치와 단위를 산식·대입값·입력·단계·자원·가정에 연결
- **사양 선택:** 세션 내 기준안과 현재안 비교, 선택적 목표 시간, 현재 사양·효과·가정 요약

P0는 서버·로그인·DB 없이 로컬에서 사용하는 것을 목표로 합니다. 모델 전체 실행, 제품별 하드웨어 프리셋, FlashAttention·Decode, 불균등 MoE, 물리 링크 라우팅, Rack 분석과 자동 설계 탐색은 후속 범위입니다.

## 실행

Node.js `>=20.19.0`이 필요합니다.

```bash
npm ci
npm run dev
```

개발·검증 명령:

```bash
npm test -- --run
npm run typecheck
npm run build
npm run preview
```

`npm run build` 결과는 `dist/`에 생성됩니다. 앱은 로컬 브라우저 안에서 계산하며 서버나 저장소를 사용하지 않습니다.

## 분석 결과를 해석할 때

- 모든 계산은 문서에 명시된 단순 모델과 가정을 따릅니다. 실제 장치 동작을 재현하는 시뮬레이터가 아닙니다.
- 단계 사이의 실행은 순차적이라고 가정합니다. 단계 내부 중첩은 정의된 모델이 있는 경우에만 반영합니다.
- 제안 기본값은 구현 출발점입니다. 실제 하드웨어 사양이나 측정된 효율로 해석하지 않습니다.
- 제품별 프리셋은 공식 자료, 단위, 집계 범위와 모델 적용 가능성을 확인한 뒤 추가합니다.

## 구현과 후속 계획

P0 완료 판단에는 코드 자동 검증 외에 [06 구현·검증 계획](06-implementation-and-validation.md)의 브라우저 상호작용, 반응형·키보드, 사용자 판단 인수 항목도 필요합니다. 아직 확인하지 않은 항목은 완료로 간주하지 않습니다. P1에는 메모리 모델 개선을, P2에는 제품 프리셋과 실측 검증 범위 표시를 추가합니다. 이후 Multi-GPU/Rack 분석과 DSE로 확장합니다.
